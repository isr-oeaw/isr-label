{% trans "Projects and access" %}

{% comment %}Screenshot suggestions: project detail header with visibility/status; Team/members page showing roles; optional staff-only project list if documenting internally.{% endcomment %}

{% blocktrans trimmed %}A project groups images, label schemas, and members. Access depends on project visibility and your membership.{% endblocktrans %}

  • {% blocktrans trimmed %}Private projects are visible only to the owner, members, and administrators.{% endblocktrans %}
  • {% blocktrans trimmed %}Public projects can be seen by any signed-in user for discovery; labeling still follows dataset and role rules.{% endblocktrans %}
  • {% blocktrans trimmed %}Restricted projects may require special management permissions to view—ask your administrator if you cannot open one.{% endblocktrans %}

{% blocktrans trimmed %}Each invited member has a project role. The following section describes each role.{% endblocktrans %}

{% blocktrans trimmed %}The project list shows projects you own or belong to, plus any public projects. Use it to open a project and its labeling area.{% endblocktrans %}

{% trans "Project roles" %}

{% comment %}Screenshot suggestions: Team/members page with roles; or invite dialog showing role choices.{% endcomment %}

{% blocktrans trimmed %}These roles control what someone can do inside a single project. The project owner always has full administrator powers for that project.{% endblocktrans %}

{% trans "Administrator" %}

{% blocktrans trimmed %}Administrators manage the project: invite or remove members, assign roles, edit project details, configure label schemas and datasets, upload images, and create labeling tasks. They can label, participate in review, and download labeling exports.{% endblocktrans %}

{% trans "Reviewer" %}

{% blocktrans trimmed %}Reviewers check submitted annotations and move work through review (for example approve, reject, or request changes). They can usually label tasks as well when they need to. They can download exports, but they do not manage membership or project/schema setup.{% endblocktrans %}

{% trans "Annotator" %}

{% blocktrans trimmed %}Annotators focus on labeling: they open tasks, draw or choose labels according to the schema, and submit their work. They do not change other people’s review status or manage project settings. Exporting bundled results is typically limited to administrators and reviewers.{% endblocktrans %}

{% trans "Viewer" %}

{% blocktrans trimmed %}Viewers can browse project content they are allowed to see but cannot label or review. Use this role when someone should follow progress without changing data.{% endblocktrans %}

{% trans "Labeling workflow" %}

{% comment %}Screenshot suggestions: per-project labeling dashboard (my tasks table, Label next); labeling task page with image canvas, tool bar, and submit.{% endcomment %}

{% blocktrans trimmed %}A task is one labeling job for an image under a schema. Tasks can be pending or done after you submit valid labels (or the rules allow empty submissions).{% endblocktrans %}

  • {% blocktrans trimmed %}While you work, a soft lock helps reduce duplicate work; it expires if unused.{% endblocktrans %}
  • {% blocktrans trimmed %}Your work is saved as a draft until you submit; then it becomes a submitted annotation subject to review rules.{% endblocktrans %}
  • {% blocktrans trimmed %}Tools (boxes, polygons, points, classification) and keyboard shortcuts depend on how the project schema is configured.{% endblocktrans %}

{% trans "Datasets and assignments" %}

{% comment %}Screenshot suggestions: project detail label-datasets section (cards with image counts); dataset assignees UI; image upload or “create tasks” control as shown to admins.{% endcomment %}

{% blocktrans trimmed %}Images live in label datasets inside a project. Administrators can upload images and generate tasks from them.{% endblocktrans %}

{% blocktrans trimmed %}Datasets can restrict labeling to certain users or groups. Open datasets (no assignees) can be labeled by anyone allowed to label in the project.{% endblocktrans %}

{% blocktrans trimmed %}On the home dashboard and project labeling page, your tasks follow these rules: project owners see tasks tied to their assignee slice; other users see tasks allowed by dataset visibility. That keeps queues predictable for teams.{% endblocktrans %}

{% trans "Review" %}

{% comment %}Screenshot suggestions: project review list; optional detail of a submitted annotation or status control as reviewers see it.{% endcomment %}

{% blocktrans trimmed %}Reviewers and project admins can inspect submitted annotations and drive review status (for example submitted, approved, rejected, or needs revision) according to the project workflow.{% endblocktrans %}

{% blocktrans trimmed %}Annotators typically submit work; changing final review states is limited to reviewer and admin roles.{% endblocktrans %}

{% trans "Export" %}

{% comment %}Screenshot suggestions: project detail export card or download control visible to allowed roles; optional ZIP download confirmation or format checklist.{% endcomment %}

{% blocktrans trimmed %}Project labeling results can be exported as ZIP bundles with COCO and YOLO formats.{% endblocktrans %}

{% blocktrans trimmed %}Export actions are limited to users with permission (usually admins and reviewers). If you need an export, ask a project administrator.{% endblocktrans %}
